# Banda Lonchera Promotion — SHCC

## Purpose and scope
Monthly, relatively lightweight networking lunch promotion for the Solano Hispanic Chamber of Commerce. This is **not** the generic event-promotion workflow. Do not apply it automatically to mixers, workshops, ribbon cuttings, galas, or paid events, which may require different instructions.

## Working principles
- Reuse the existing format; do not make Leo re-explain established preferences.
- Be accurate. Ground logistics, speaker, venue, registration status, and costs in the CURRENT event flyer, official event page, and user instructions; never copy a previous month's facts.
- Short, practical, community-centered marketing. Lead with reasons to attend: local owners, connections, supporting the host restaurant, and any short educational talk. Do not turn a short talk into a full workshop or product pitch.
- Avoid unnecessary approval bottlenecks. Once Leo delegates an execution task to staff, they may adapt, schedule, and publish within provided parameters without waiting for repeated approvals. Escalate only missing essential information, inaccessible assets, or substantive conflicts.
- Respect latest user instructions over these defaults.

## Inputs and initial verification
1. Collect the current Banda Lonchera flyer or official source, event date/time, restaurant and complete address, event focus, source Drive folder, and existing SHCC Asana parent task if any.
2. Check whether the event Drive folder, flyer, event page, and parent Asana task already exist. Reuse and update instead of duplicating.
3. Confirm ambiguous details rather than inventing them. Do not assume a cost, end time, RSVP requirement, or published URL.
4. For the November 2026 example only, no registration/RSVP was required. Treat that as a **per-event fact**, not a universal rule: check each month's directions.

## Folder and Asana parent task
1. Create or reuse a dated Google Drive folder within the SHCC event assets location the user specifies. Put or reference flyer, event-page content, social plan, and email/SMS plan there.
2. Create/reuse one parent Asana task in **SHCC projects**, assigned to Leo unless instructed otherwise. Include event summary, folder URL, source flyer, all documents and relevant subtasks.
3. Derive due dates from current user instructions and calendar, not from the previous month's dates.
4. Do the initial requested step only if Leo asks to work in phases. Do not prematurely create the full campaign.

## Event listing / event-page document
- Before creating a new event page, **check if an unpublished/draft page already exists**. Update and publish existing page if present; avoid duplicates.
- Prepare a clearly formatted Google Doc with event title, short summary, English and (when useful) Spanish event description, exact details, SEO/meta title, meta description, search phrases, URL slug idea, image alt text, and publication checklist.
- Event page is informational unless the current event requires registration. Never enable RSVP, registration, prices, or ticket buttons without support.
- Verify live public page after publishing. Return its URL to parent task and other promotion work. Never substitute an editor/draft URL.
- Assign the event-page subtask to **Vivian** with instructions in **Spanish**, unless Leo overrides.

## Social media plan and subtask
- Prepare a Google Doc with verified logistics, a **suggested** publishing schedule, differentiated Facebook and Instagram draft captions, flyer and venue imagery suggestions, and one main CTA. A short Spanglish or Spanish variation may be suitable. Maximum **3 hashtags per post**.
- Typically propose an announcement, a benefit/mindset post, a local restaurant/community post, and a final reminder, plus optional story. Adapt to lead time and the particular month's focus.
- Lead with people and benefits, not a text-heavy flyer. Suggest restaurant collaboration posts where appropriate and with the host's agreement.
- Social copy must work without a registration link if the event needs no signup; optional event-page URL is for more information.
- Assign social media to **Sumeen**, instructions in **English**. Give her freedom to draft extra variations, vary the angle/visual, reschedule sensibly, and publish within the brief **without waiting for Leo's approval**. She should leave a brief task update listing scheduled/published content.
- Flag missing access or factual blockers only; do not impose needless copy approvals.

## Constant Contact email and SMS
- Create a dedicated dated Google Doc for these channels, normally BEFORE creating the execution subtask if Leo wants to review in stages.
- Usually suggest **2 email campaigns** (announcement + final reminder), with optional third only if useful. Include subject, preheader, concise body, flyer placement, event details in text, and a single informational **View Event Details** button with the **live** event page URL. Registration CTA only when current event truly needs registration.
- Usually draft **2 English SMS messages**: initial announcement and early-in-event-month reminder. Keep each final message **under 140 characters**, including short URL, spaces, and any required opt-out suffix. Never invent a shortened URL.
- The SMS platform may consume credits when FUTURE sends are scheduled. Instruct Vivian to check balance, recharge date, and provider behavior. If sufficient credits, schedule both. If not, schedule first and set a real dated follow-up to return early next month for the second; **do not claim an unscheduled SMS is scheduled**.
- Require Vivian to obtain the **live event page URL from her completed event-page subtask**, verify it, shorten it with the authorized tool for SMS, and use the same link in Constant Contact.
- Assign email/SMS preparation to **Vivian** with **Spanish instructions**. Make links to the Google Doc, flyer, event folder and event-page subtask easy to find.
- Do not confuse drafting with actual sending or scheduling. Report status accurately.

## Quality check and final response
- Confirm each requested folder, document, assignment, due date, and Asana relationship through the connected tools.
- Verify Google Drive access where permitted. If file sharing fails, tell Leo exactly which asset needs attention; do not claim access was granted.
- Avoid duplicating task/document creation when rerun.
- Summarize what was created, link artifacts, and separate completed work from pending work.
- Keep instructions concise, especially for staff; reference the fuller Google Docs for examples.
